# P4 真实聊天数据导入

P4 将“安全获得聊天记录”与后续整理链路解耦。用户已有的 TXT、JSON、JSONL、CSV、XLSX 或粘贴文本会先在本机内存中做确定性解析；预览展示会话、计数、时间、发送者、消息类型、样例、未解析行和 warning。未经确认不写入 SQLite。

CSV/XLSX 使用明确列名映射；自动建议不可用时，页面可人工重选列并重新生成预览。TXT/粘贴只支持两种公开格式：“完整日期时间 + 发送者 + 下一文本块”，以及 `[HH:MM] 发送者：内容`。只有时间而没有日期时，必须人工给出默认日期。没有会话时，必须给出默认会话名称或 ID。只有日期、夏令时下不存在/不唯一的本地时间会保持未解析；当前对 XLSX 1904 日期系统明确拒绝，不会静默错移日期。

每次确认导入都会创建独立 import ID、batch ID 和密封 snapshot ID。源文件 SHA-256、映射选项、来源类型和平台提示纳入预览指纹。规范消息 ID 使用既有稳定身份规则；手动导入的账号、会话和消息身份按“原始文件 + 已确认解析选项”的确定性指纹命名空间化，既防止两份文件都使用 `c1` 时串扰，也允许同一文件按不同时区/映射安全重新解释；原始文件指纹仍保留为 provenance。重复消息计数，同一源消息 ID 的不同负载列为冲突，不覆盖既有消息。

导入请求体、单文件、ZIP/XLSX 展开大小、行列数、会话数、字段长度和预览问题明细均有硬上限。XLSX 单元格引用在整数计算前即按 Excel 物理范围和配置列上限拒绝，避免异常长引用造成大整数资源消耗。未确认预览默认最多同时保留 8 个、原始输入合计不超过 128 MiB，每个本地浏览器会话只保留最新一个（字段映射刷新会安全取代旧预览），并在 TTL 到期时从内存清理。缓存仅保留原始字节、计数和增量摘要，不长期持有规范化消息对象；提交时从缓存的精确字节重新分析并以恒定时间比较摘要。

确认后不建第二套索引：数据直接进入现有 canonical message、batch membership 和 immutable snapshot，再由原 Search、exclusion、外发预览、Generation、evidence 和 Document 服务处理。手动搜索同时绑定所选导入的 snapshot，重复导入不会把旧句柄的结果替换成新批次。整个导入登记与快照密封处于同一 SQLite 事务；冲突时整笔回滚。无法按会话可靠归因的重复/解析错误不会复制到每个会话证据中，全局计数仍保持精确。

页面会分页显示当前本地浏览器会话已确认的所有导入。刷新页面时，同源 HttpOnly 会话 cookie 可在首次签发后的 7 天绝对恢复窗口内续期短期活跃租约；超过绝对期限会换发新会话，旧 cookie 不能无限复活。后端为每个恢复批次重新签发短期不透明会话句柄，并返回该批次提交时确认的显示时区；不会把内部 conversation ID 暴露为选择凭据，也不会用新导入表单的时区重解释已提交批次。旧数据库会话迁移只沿用原短期到期时间，不扩大已有权限。分页 cursor 自含严格校验的排序键，因此即使先删除当前页末批次，仍能继续加载更早记录。每个批次都有独立的影响预览和二次确认删除入口；相同消息仍被其他批次引用时只删除目标批次并明确保留共享消息。

预览失败只返回不含原始内容的白名单错误类别。界面会分别提示不支持格式、文本编码、损坏的 XLSX/ZIP、字段映射或安全上限问题及对应恢复方式，不会在错误中回显聊天正文。

## Accessibility POC 边界

`tools/accessibility_poc` 是独立开发工具，不集成正式抓取功能。它只使用 Apple `NSWorkspace` 与 `AXUIElement` API，默认自检只看应用是否安装/运行和版本，不创建 QQ/微信 AX 元素。目标检查需独立显式参数，只遍历当前前台窗口，不滚动、不点击、不输入。本轮仅运行无内容自检：检测到 QQ 7.0.1 与微信 4.1.13 已安装、当时未运行，且当前工具未被授予 Accessibility 权限。没有读取真实聊天，所以 QQ/微信的正文、发送者、时间戳和顺序能力仍为未测试，不做成功声明。

任何未来 Gate 2 都必须使用专用非敏感测试会话和用户正常授权。如果 AX 树只暴露 Window/Group/ScrollArea/Button 而没有稳定正文，该路线必须立即 NO-GO，不得转向内存、数据库密钥、注入、修改客户端或关闭 SIP。
