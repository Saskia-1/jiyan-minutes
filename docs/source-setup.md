# QQ 与微信来源配置

## 共同边界

平台只连接固定回环地址：QQ 候选 `127.0.0.1:40653`，微信候选 `127.0.0.1:6131`。回环地址表示同一台电脑，但仍须 Token、浏览器会话、CSRF 和一次性授权。平台不会安装或启动工具，不会登录账号，不会自动授予完全磁盘访问，不会关闭 SIP、提权、扫描进程内存、修改或重签名 QQ/微信。

只有未来候选先通过来源、二进制、许可和兼容性 Gate，才进入以下接入顺序：安全检测版本 → 阅读完整来源披露 → 用户在来源工具中自行完成已批准初始化 → 在平台保存公开版本信息 → 通过独立确认将来源 API Token 保存到 macOS Keychain → 列出会话元数据 → 用户选择账号、会话、起止时间与目录 → 再次确认 → 窄范围真实导出。会话列表阶段不读取正文。当前两个发布物均未通过 Gate，不能执行这条流程。

生产运行时会把两个来源显示为 `blocked`，并同时在前端禁用与后端拒绝保存配置、列会话、验证导出、Token set/get 和新建来源导出范围；直接调用这些 API 也返回失败，且不会触发适配器或秘密存储读取。为了可清理既有状态，“删除已保存 Token”和“断开来源”仍保留。

## QQ / QCE

锁定候选为 QCE v6.2.10 的 macOS arm64 预览资产。实际下载文件的大小和 SHA-256 与 Release 元数据完全一致，但离线静态审计为 NO-GO：核心文件只有 ad-hoc 签名或未签名，没有 Developer ID/公证/Gatekeeper 接纳证据；原生模块包含 Frida 与进程内 Hook/Mach 内存能力；launcher 会清除扩展属性、复制和弱化重签名 QQ 副本、创建真实数据链接，并可能移动既有链接目标。包内许可/原生供应链材料也不完整。本机 QQ 为 7.0.1 build 52892；上游没有这一精确组合的实机记录。其服务实现还可绑定 `0.0.0.0`，本地桥端口冲突处理可能终止未验证归属的进程。因此：

- 当前状态：`blocked / NO-GO / 真实导出未实测`；只审计了私有临时目录中的发布物，本项目未安装/启动 QCE。
- 不把健康检查、文档或 standalone view 当成导出成功。
- 当前发布物不进入初始化或真实小范围测试。只有发布者身份/公证、许可与原生来源、本机 QQ 兼容性及回环/端口控制得到新的可验证证据后，才另行制定重新评估方案。
- 取消只能阻止平台后续请求，不能撤销 QCE 已开始的同步读取或其自身缓存/运行副本痕迹。

常见失败：工具未运行、Token 无效、standalone 模式返回 503、QQ 账号/版本变化、分页证据异常、历史不完整、输出目录权限/空间不足。任何错误都不得改用更大范围读取。

Ultra Gate 1 的完整证据见 [`ultra-gate-1-research.md`](ultra-gate-1-research.md) 和 [`ultra-gate-1-binary-audit.md`](ultra-gate-1-binary-audit.md)。

## 微信 / TraceMemo

候选为 TraceMemo v2.3.0。实际下载 DMG 的大小和 SHA-256 与 Release 元数据完全一致且 CRC 有效，但离线静态审计为 NO-GO：DMG 未签名；App 无 Developer ID/Team ID/Hardened Runtime，深度严格签名校验失败，关键 helper/库签名无效，Gatekeeper 未接纳且没有有效公证票据。固定源码根包版本 2.2.3 与发布包内 2.3.0 不一致；产品许可证、SBOM 与原生组件来源仍不完整。首次启动的静态代码会开启 API/Agent Hub、执行连接器账号枚举、启动调度器并检查 GitHub 更新；同一广权 Token 还覆盖发送/定时任务写能力。当前微信 4.1.13 也不在上游公开已测试组合内。自动数据库取钥要求 SIP 检查、管理员授权并扫描微信进程内存，继续被明确禁止。即使用户合法持有当前账号的正确数据库密钥，也不使用这一发布物进行手动初始化；本平台仍不会索取、接收、保存、记录或显示数据库密钥。

- 当前状态：`blocked / NO-GO / 真实导出未实测`；只审计了只读挂载的发布物，镜像已卸载，本项目未安装/启动 TraceMemo。
- 当前静态包检查已经不通过，因此停止在安装之前；不以现成密钥绕过这一结论。
- chatlog 没有已验证的 HTTP 分页/完整性信号，成功读取也只能标记 `unknown`，不能声称完整历史。
- 工具可能有联系人/消息缓存、更新检查及可选 AI/Agent/反撤回功能；平台不启用也不调用这些接口，但不能代替工具侧审计与清理。

Ultra Gate 1 的完整证据见 [`ultra-gate-1-research.md`](ultra-gate-1-research.md) 和 [`ultra-gate-1-binary-audit.md`](ultra-gate-1-binary-audit.md)。

## Token 的保存与删除

下述流程只适用于未来通过 Gate 的候选： “查看令牌保存确认”只生成一次性、短期、会话绑定的确认；勾选后“保存 Token”才通过标准输入写入 macOS Keychain，浏览器不再收到秘密值。列会话和导出分别需要 `secret_get` 授权且一次消费。当前 blocked 状态不签发 set/get 确认；“删除已保存 Token”仍可使用独立 `secret_delete` 确认，删除后可断开来源配置。

“断开来源”只忘记本平台连接配置、选择句柄和未用授权。它不删除已经导入的快照/文档/文件，不删除 QQ/微信原始记录，不清理 QCE/TraceMemo 缓存，也不撤销 macOS 权限。具体差异见 `docs/privacy-and-cleanup.md`。
