## 产品定位与目标

面向通过微信、QQ 推进项目的工作者，在用户意识到某段对话值得保留时，帮助其筛选主题相关信息，整理为可供个人复盘的摘要和主题文档，并保存到本地选定位置。

产品以现有平台的导入、筛选、四种整理方向、人工编辑和下载流程为基础。第一版的核心价值是让用户用更少的整理时间，保留对项目有价值的认识、想法和经验，同时忠实保留原始信息的条件、分歧与未定事项。

产品目标：

- 从分散、夹杂闲聊的对话中筛出与指定主题相关的信息。
- 将零散表达组织为自然、清晰、方便复盘的内容，降低用户自行概括的负担。
- 让用户能确认整理范围、校正结果，并持有独立的本地文档。
- 限制独立原始资料在平台内的保留时间（7 天，或由用户提前删除），同时长期保留用户已经形成的整理成果。

## 用户与使用场景

### 核心用户

经常通过微信、QQ 讨论和推进项目，需要将讨论中的观点、想法、做法及经验沉淀下来供自己复盘的工作者。首版沿用当前 macOS 本地单用户应用形态。

用户是否担任项目经理、项目属于何种行业，以及使用频率，尚未限定；这些属于后续访谈与试用需要验证的人群特征。用户需自行确认有权处理所导入的对话内容，见“使用前合规提示”。

### 触发场景

一段项目对话产生后，用户意识到其中的分析、建议或经验值得保留，希望及时整理。相关信息可能穿插在其他话题中，也可能需要结合前后文才能理解。

示例场景，供需求评审使用：用户与同事讨论项目延期的原因和改进办法，讨论结束后，希望整理各方判断、适用条件及经验建议，方便自己下次推进相似项目时复盘。

### 核心用户任务

当我发现某段项目聊天有价值时，我希望选出与主题相关的内容，并将它整理为忠实、易读的文档，以便以后复盘和参考，减少反复翻找聊天和手动归纳的时间。

## 用户流程

1. **提供资料**：导入受支持的聊天文件或截图。保留现有粘贴入口，但不扩大首版输入范围。首次使用需先确认合规提示。
2. **检查输入**：查看解析结果；截图先校对识别文字，再确认导入。时间或发言人无法识别时保持未知，界面明确标注；未知时间正文默认不纳入检索与生成，用户勾选“包含时间未知的聊天与笔记”后才纳入；未设置时间范围时沿用现有纳入逻辑。
3. **指定目标**：输入主题，选择现有四种整理方向之一；可选填本次复盘目的（拟定上限 200 字）。
4. **筛选内容**：在选定来源和范围内检索相关信息，检查上下文候选，剔除无关内容或选取需要的正文。
5. **确认生成范围与外发**：查看实际将发送给外部 AI 的脱敏文字与检索主题，勾选本次授权后才发起请求。主题关键词扩展继续沿用已有的单独说明。
6. **阅读与修改**：查看归纳结果和独立标识的专业补充；原文仍可用时按需核对依据；可以编辑并保存新版本。
7. **保存文档**：选择 Word 或 Markdown。平台把文档写入已批准的本地导出目录；浏览器支持保存选择器时，用户可另存到自选位置，否则沿用浏览器下载行为并明确提示。完成后提示“应用内往期列表受当前浏览器会话 7 天窗口限制，请保留另存文件”。
8. **清理原文**：用户形成归纳后可选择提前删除独立原始资料；否则自确认导入起 7 天后自动清理。最终文档与已另存文件保留。

## 功能要求与验收标准

### 输入与筛选

- 聊天文件、截图均先预览、后确认；解析或识别失败必须说明问题。聊天文件部分解析成功时，预览显示有效记录数、未解析记录数及原因，用户单独勾选“接受跳过 N 条未解析记录，仅导入 M 条有效记录”，再确认导入；默认不接受跳过，变更输入或字段映射后须重新确认。未解析记录不进入索引、检索与生成，导入结果及往期批次显示实际导入和跳过数量，不得声称全部导入成功。没有有效记录时禁止提交。
- 截图沿用现有最多 20 张及 PNG／JPG／JPEG 格式限制；超限时提示调整输入。
- 用户能指定来源、主题及已有的时间范围，能检查实际纳入整理的正文。
- 未知时间的正文不推断时间：只有手动导入来源可能存在未知时间正文，默认不纳入检索与生成，需用户显式勾选“包含时间未知的聊天与笔记”后才纳入；未设置时间范围时沿用现有纳入逻辑。评估脚本的内部放行开关不作为产品默认行为。
- 关键词扩展只帮助召回相关信息，不作为聊天事实，也不等同于网上专业资料检索。
- 用户排除或未勾选的正文不能在生成阶段被自动补回。
- 找不到相关内容时，提示调整主题或范围；不能以无关材料生成看似完整的复盘。

### 使用前合规提示

- 首次使用（含提示文案变更后的版本）显示提示，用户勾选“我已知悉”后才能进入导入；导入确认界面常驻一行入口，可随时再次查看。
- 文案必须包含：请确认你有权整理该对话（可能含他人个人信息）；生成时主题相关内容会脱敏后发送给外部 AI 模型；平台不识别保密等级，请勿导入涉密或无权外发的材料；文档与依据附录会长期保存在本机，原文自确认导入起 7 天后清理。
- 勾选状态与提示版本只记录在本地，不记录聊天正文。
- 验收：未勾选无法导入；提示可再次打开；文案包含上述四项。

### 整理方向与目的

沿用现有四种方向，不统一强制套用会议纪要模板：

| 方向 | 主要整理内容 | 约束 |
| --- | --- | --- |
| 观点 | 主要判断、理由、取舍和分歧 | 保留判断的适用范围与条件，不将个人经验写成普遍事实 |
| Idea／想法 | 独立构思、目标、机制及未定部分 | 不因话题相近而强行合并不同构思，不补造已经确定的方案 |
| 方法论／怎么做 | 已提出的做法、步骤、条件、注意事项和经验 | 没有依据时不补造完整操作流程；沿用现有指南字段呈现 |
| 综合整理 | 围绕主题整合有价值的信息 | 根据内容组织章节，不强制产生决定、待办等栏目，不重复输出相同信息 |

新增目的说明为可选项，拟定判据：

- 输入上限 200 字；留空时不追问、不阻塞，直接使用当前主题与方向完成整理。
- 目的只用于调整表达重点、章节顺序与详略；不得改变事实含义，不得改写状态（提议、猜测、备选、未决），不得引入聊天中未出现的内容。
- 目的文本出现在外发预览中，用户确认后才发起请求。
- 验收方法：固定主题、来源范围、方向与模型配置，仅改变目的字段重复生成，对照人工标注结果检查——关键保留点全部保留，且没有新增聊天中未提及的信息。记录方式沿用现有质量验收记录的每次评估记录项。

### 内容质量

验收目标：归纳内容不得出现事实性错误。验收分为信息忠实性、信息完整性、表达质量和补充边界，不用“原文依据校验通过”替代语义正确性验收。

- **事实与状态**：不虚构人物、数字、时间、原因、步骤或决定；不将提议、猜测、备选或未决事项写成确定结论。
- **条件与分歧**：保留影响理解的前提、限制、纠正和分歧，不擅自替讨论各方形成共识。
- **关键信息**：按所选方向保留对复盘有意义的独特内容；不能因压缩篇幅而丢失关键条件或相互独立的观点。
- **自然表达**：把相关信息融合为连贯段落，归纳出共同含义，避免逐条换词和机械拼接。允许保留原本就清楚、准确的相同措辞。
- **主题一致**：整理围绕用户选择的主题和目的；不把泛泛建议作为正文主体。
- **证据不足**：明确不足或未定之处，不编造填满内容。

重大错误定义为会改变复盘结论的事实错误、虚构内容、状态误判、关键条件缺失或分歧被抹平。首轮验收样例出现重大错误时，该样例不通过。通过有限样例不代表对任意输入保证零错误。首轮验证的样本量与通过阈值见“验证方案与产品指标”。

### 外发授权与脱敏

- 生成（含联网专业参考检索）前，界面展示将要外发的完整脱敏正文与检索主题，用户逐次勾选授权后才发起请求；未授权不得外发，也不产生费用。
- 外发内容仅限文字；附件、媒体、数据库、来源 Token 与 API Key 不外发。
- 脱敏为本地规则处理，须提示“不保证覆盖全部人名、联系方式等个人信息”，不得暗示完全匿名。
- 默认每日最多 100 次 Provider 请求；达到上限时明确提示并保留稍后重试入口，不静默失败。
- 取消请求可能发生在供应商已收到请求之后，仍可能产生用量与费用，取消界面须说明这一点。
- 外发预览与授权为一次性，过期、消费或取消后不可重放；已产生的用量记录不含聊天正文。

### 专业补充与网上参考

核心归纳和专业补充分开呈现。专业补充应直接帮助理解原主题中的具体问题，不取代聊天整理，不大幅扩展为新的方案或其他话题。

现有 AI 延伸解释继续标明其性质，不显示未经核实的网上来源。

新增联网专业参考的拟定要求：

- 用户可选择是否获取网上参考；仅在确有帮助且启用该能力时执行，并受“外发授权与脱敏”约束。
- 优先查找与原主题直接相关的专业或一手来源，并提供可打开的来源链接及必要的时间信息。
- 将参考意见标为外部补充，不混同为聊天参与者的观点或已经作出的项目决定。
- 检索请求采用最少必要的主题信息，外发前说明范围，避免将整段项目聊天直接用于网上搜索。
- 检索失败或没有合适来源时，核心归纳仍可完成，不编造参考资料。

是否将联网检索纳入首个发布版本尚待确定；这一点不影响沿用现有平台形成核心流程。

### 编辑与文件保存

- 保留全文编辑和历史版本能力；保存后预览与下载使用同一已确认版本。
- 用户未确认的编辑不混入已保存结果。
- 最终文档能独立阅读，不依赖应用或原始资料始终存在。
- 保留 Word、Markdown 两种格式。保存路径写实：平台把文档原子写入已批准的本地导出目录（默认 `~/Documents/Chat to How-To Exports/documents`）；支持保存选择器时，写入用户选定位置后才显示“已保存到…”，否则只提示“已发起浏览器下载”，不得声称文件已保存；写入失败时显示尚未保存，并允许重新选择位置。用户取消选择不视为失败，但不得显示保存成功。
- 文档保存不设期限：在用户主动删除前，平台内的文档与保留版本一直存在，包括原文 7 天到期清理之后。
- 首版的应用内往期查看受浏览器会话 7 天窗口限制（现有“已生成文档”列表）；首版不解除该限制，保存完成后引导用户使用“另存为”持有文档，并明确提示应用内列表可能在第 7 天后不再显示。解除会话绑定并提供长期往期查看列为 P1。
- 正文自然归纳原始信息，依据不作为必需的正文组成。附带依据属于现有可选行为，不作为默认产品目标。
- 验收：保存完成后必须出现另存为引导与应用内列表 7 天时限提示；保存选择器不可用时显示下载回退说明；未写入用户选定位置或未完成下载时，不得出现“已保存”字样。

### 原文保留与删除

已确认的原则：**独立原始资料自确认导入起保留 7 天，用户可提前自行删除，到期后停用并触发清理；最终文档与用户已保存、已另存的文件不受影响。物理删除以应用可运行且清理未中断为前提，不涉及供应商、操作系统备份或用户自存文件中的副本。**（本节原则只针对新增的 7 天自动清理与提前删除路径；现有“删除批次”入口仍会连带删除关联文档，见下方补充约定。）

执行规则：

- 计时起点为该批次确认导入完成时刻，界面显示具体到期时间；同一批资料重新导入按新批次重新计时。
- 既有批次恢复与逐批删除入口以这 7 天为期限上限：原文到期后不再列出该批次，避免出现“会话还在但原文已停用”或“会话已过期但原文尚未到期”的错位。
- 到期即停止继续检索和使用该原文；应用运行时清理，未运行时在下一次启动先清理再恢复业务。首版沿用本地应用，不承诺关机期间完成物理删除。
- 到期前可提示尚未导出的结果；清理不以用户完成归纳为前提，也不因生成失败自动延长保留期。
- 提前删除前展示“删除哪些原始资料、保留哪些文档、哪些依据将不可再查看”。
- 删除后，文档正常阅读、编辑和下载；依据入口显示原文已删除，不展示失效内容，不再暗示可以实时回溯原文。
- 普通原文清理不等同于从供应商、操作系统备份或用户自存文件中撤回内容。

| 数据类别 | 保留方式 |
| --- | --- |
| 平台管理的导入原始资料、规范化聊天正文、截图和 OCR 正文、粘贴笔记 | 纳入 7 天保留与提前删除范围 |
| 可还原独立原文的内部副本：不可变快照、全文索引、外发预览缓存、待确认预览缓存、过程记录、内部依据副本 | 随相关原文清理；混合来源和多批次引用需要统一处理，避免遗留副本 |
| 平台写出的原子导出批次与 manifest（已批准导出目录下的 `exports/`）、清理中断时的暂存文件 | 属平台产出的原文副本，随相关原文清理；用户已另存到其他位置的文件不受影响 |
| 最终文档、用户修改和保留的文档版本（含内嵌依据附录） | 保留，不设期限；其中与原文相同或摘录自原文的内容不做全文匹配删除 |
| 平台之外的微信、QQ 聊天、用户自行持有的输入文件及自行保存的输出文件 | 平台的原文清理不删除这些文件或记录 |

补充约定：

- 保留的文档版本允许内嵌依据正文（章节引用与集中证据附录）。这类内容属于用户成果，随文档保留；与之相对，平台内部用于重建依据视图的依据副本随原文清理。
- 由于文档可能长期保存原文摘录，界面与导出的文档须披露：“本文件包含原始对话摘录；删除原文不会删除本文件中的摘录。”
- 披露验收：文档预览页、导出的 Markdown／DOCX 与保存完成提示中，均须出现上述披露文本。
- 现有批次删除会影响关联文档，不能直接作为“仅删除原文”的实现。新增清理须覆盖所有相关副本，同时保留最终文档，避免误删用户成果。
- 清理正确性验收：到期或手动删除后，扫描私有数据目录与已批准导出目录（含暂存目录），确认不存在可还原独立原文的副本，且最终文档与版本完整可打开。

## 首版范围与优先级建议

P0 表示核心发布要求；P1 表示建议在核心流程稳定后完善。以下优先级为本稿建议。

| 优先级 | 范围 | 处理方式 |
| --- | --- | --- |
| P0 | 聊天记录与截图导入、预览与校对 | 沿用现有能力（支持格式与张数上限见“已确认需求与现有平台对照”与“输入与筛选”），验证真实项目材料 |
| P0 | 主题筛选与四种方向归纳 | 沿用现有能力，完成真实模型内容验收 |
| P0 | 人工编辑、本地保存与下载 | 沿用现有流程，把现有“下载文档”入口改为明确的“另存为”引导（含保存位置与失败提示），核实保存反馈与文档可用性 |
| P0 | 独立原文 7 天保留与文档长期保留 | 新增解耦能力、7 天清理、手动提前删除与副本统一清理 |
| P0 | 生成目的说明 | 增加可选输入，与现有主题、方向保持一致，并通过判据验收 |
| P0 | 外发授权、脱敏提示与每日上限 | 沿用现有能力，补成文验收，未授权不外发 |
| P0 | 使用前合规提示 | 新增首次提示与导入页常驻提示 |
| P1 | 应用内往期文档查看（解除会话绑定） | 首版以“另存为”引导替代 |
| P1 | 带来源的网上专业参考 | 新增检索与引用能力，先确定是否进入首发 |
| P1 | 产品内结果评价入口 | 首版用人工验收判定替代，见“指标定义” |

首版沿用本机单用户形态。暂不纳入：团队协作、跨设备同步、自动持续读取聊天（不自动登录账号、读取聊天目录、获取数据库密钥或提权）、项目管理任务系统、收费系统、向量检索、新 Provider 接入、会议纪要实体或模板、新增来源类型、取证级擦除、云同步、关机期间完成物理删除、自动付费重试。如后续需要，应单独定义需求。

## 异常与恢复

| 情况 | 用户应得到的反馈与处理 |
| --- | --- |
| 文件不支持或解析失败 | 显示具体可操作的修正方式，保留重新导入入口 |
| 截图识别不清楚 | 允许校对、裁剪后重试；未知信息不自动补造 |
| 筛选没有命中或依据不足 | 提示调整主题和资料范围，不强行生成结论 |
| AI 超时、失败或输出不合要求 | 保留清晰的任务状态，允许用户显式重试；不以错误结果冒充成功 |
| 未配置 API Key 或认证失败 | 本地导入、筛选、查看与已保存文档编辑仍可用；生成入口说明具体原因 |
| 达到每日请求上限 | 明确提示当日上限已到，保留稍后重试入口；不外发、不静默失败 |
| 用户取消生成或下载 | 说明请求可能已被供应商接收、仍可能产生费用；本地结果与文档不受影响 |
| 联网参考失败 | 标明该补充未取得，保留核心归纳结果 |
| 用户取消另存或文件写入失败 | 显示尚未保存，允许重新选择位置或下载 |
| 原文已删除 | 文档继续可用，依据不可再查看；已另存文件仍可正常打开；重新整理需再次提供资料 |
| 浏览器会话窗口过期 | 应用内往期文档列表不再显示；提示使用已另存文件，不声称文档数据丢失 |
| 合规提示未确认 | 不进入导入流程，提供再次打开提示的入口 |
| 清理中断 | 显示实际清理状态，下次启动继续清理，不提前声称删除完成 |

## 验证方案与产品指标

### 首轮验证

使用经允许的真实项目对话，覆盖夹杂闲聊、同主题多段讨论、观点分歧、后续纠正、未确定方案和截图识别错误等情况。先人工标记主题相关内容、关键保留点与明确不能得出的结论，再对照产品输出验收。

保留与授权规则单独验证：覆盖 7 天到期清理、提前删除、会话窗口边界和清理中断恢复（可用缩短保留期的测试配置模拟，不修改产品承诺）；覆盖未勾选外发授权时不发起请求、达到每日上限时不外发，以及合规提示未确认时不能导入。

现有自动测试证明部分结构与工作流程可运行。现有项目文档将真实模型质量验收标为尚未执行；产品发布前需要补齐，不能用模拟输出替代。

### 指标定义

| 指标 | 统计口径 | 作用 |
| --- | --- | --- |
| 整理完成率 | 成功保存或另存至少一份文档的整理会话数 ÷ 已开始导入的整理会话数；整理会话定义为从导入到保存文档的连续过程，30 分钟无操作断开，中途放弃的导入不计入分母 | 判断用户是否完成核心任务 |
| 可用结果比例 | 被人工验收判定为可直接复盘或仅小幅修改的结果数 ÷ 已人工验收判定的结果数；首版依赖人工验收判定，产品内评价入口列为 P1 | 判断结果是否有实际价值 |
| 重大错误比例 | 人工对照发现重大错误的结果数 ÷ 已检查结果数 | 检查核心质量底线 |
| 关键内容覆盖率 | 结果保留的人工标注关键点数 ÷ 应保留关键点数 | 检查是否遗漏重要信息 |
| 整理耗时与节省时间 | 从开始导入至保存结果的耗时，与用户整理同等材料的人工基线比较 | 验证省时价值 |
| 清理正确性 | 到期或手动删除后检查发现可还原原文残留的批次数 ÷ 已清理批次数，以及最终文档与版本是否完整保留 | 验证保留规则是否落实 |

首轮验证的样本量、重大错误上限与关键内容覆盖阈值在验证开始前确定并记录；无论阈值如何设定，以下两项为硬性条件：重大错误 0 例，未授权外发 0 次。数值目标由首轮基线试用确定，不将未经测量的提效比例写成产品承诺。统计如需记录行为数据，应另行明确采集范围，不收集聊天正文作为指标日志。
