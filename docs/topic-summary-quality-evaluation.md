## 同一输入的模式完整度清单

合成输入：

- m1：命令背得很熟，换一个报错还是不知道怎么查。
- m2：我觉得主要问题是不知道什么时候用这些命令。
- m3：可以做“从报错到定位”的练习卡。
- m4：每张卡先给报错，做完再对照排查路径。
- m5：练习时先复现，再找触发位置，做最小修改，最后重跑验证。
- m6：不能稳定复现时，先记录环境和触发条件；练习卡的具体实现还没定。

### viewpoints 必须保留

- 排查能力不只取决于记住命令，还取决于判断何时使用。
- 该判断是针对这类学习问题的理解，不得扩大成普遍事实。
- “不能稳定复现时记录环境和触发条件”是排查分支，不得写成上述观点成立的条件。

### ideas 必须保留

- “从报错到定位”练习卡的核心构思。
- 先给报错，完成后再对照排查路径的已提出用法。
- 具体实现尚未确定；不得创造平台、打分或社交等新功能。

### how_to 必须保留

- 复现 → 定位触发位置 → 最小修改 → 重跑验证的明确顺序。
- 不能稳定复现时，记录环境和触发条件。
- 练习卡实现未定，不得补造完整制作教程。

### mixed 必须保留

- 命令记忆与使用时机判断的核心认识。
- 练习卡构思及已提出的组成方式。
- 已明确的排查顺序和无法复现时的分支。
- 不得使用“聊天提出了”等来源叙述，也不得把三类内容分组后重复三遍。

## 跨领域最小验收集

| 领域 | 代表模式 | 必须保留 | 必须拒绝 |
| --- | --- | --- | --- |
| 产品或活动构思 | ideas | 构思目标、已提出的组成、未定部分 | 未提及的商业模式、竞品或 MVP |
| 技术排查 | viewpoints / ideas / how_to / mixed | 上述各模式清单 | 创造工具、参数、因果或已验证结论 |
| 学习经验 | viewpoints | 学习判断、理由、练习方式与适用条件 | 产品功能或平台化设计 |
| 职业或工作沟通 | viewpoints | 具体取舍、个人适用范围与分歧 | 把个人经验写成所有人的规律 |
| 生活方案或出行安排 | mixed | 目标、备选、天气/体力等条件、未决定项 | 把备选写成已确定行程 |

## 每次真实评估的记录项

1. 主题、模式、消息范围和排除条件。
2. Prompt 版本、Provider/模型、分块数、预计调用数和实际调用数。
3. `cache_hit` 及缓存身份所用的 Prompt 版本。
4. 样例/模式的必须保留点逐项结果。
5. 独特信息、关键条件、例子、动作和限制是否丢失。
6. 是否强行合并独立观点/构思，是否生成不受证据支持的关系。
7. 新旧对照使用的是否是相同主题、范围、模式和实际模型配置。
8. 通过、失败及尚未验证的项目；不以字数或禁用词计数单独下结论。
