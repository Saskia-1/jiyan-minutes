## 方案与取舍

采用 README 作为入口，把产品决策和实现证据放在一份案例文档，配套可导入的合成资料与现场演示提纲。仅扩充安装手册无法说明产品思考；另建展示网站会增加维护，本轮不做。Figma 原型未制作，不列为已有成果。

## 交付与约束

- 重写 README 首屏，保留必要安装、运行、配置及验证说明，明确当前流程和历史高级流程的区别。
- 产品案例讲清起因、个人职责、需求到验收的转化、Agent 能力边界、工程验证与语义质量的区别，链接实际代码和测试。
- 演示资料纯合成，不制作或展示伪造的模型结果，不把演示脚本当成真实模型验收。
- 先核对对应实现；只修确实影响任务的缺陷，不为面试添加未经需要确认的新功能，不调整 v10 总结方式。
- 不虚构用户访谈、团队协作、试用人数、提升比例、向量检索或多 Agent 能力。保留原产品名称及内部路径。

验收：材料能回答「为何做、为何这样取舍、具体如何控制、怎样知道做对了」，所有本地链接有效，样本可由现有解析器导入，技术主张与代码和测试一致。
