# 记言 · Minutes：自然语言 Agent 工作台设计

日期：2026-10-23。状态：用户已确认「按方案开发」；当前修复与首次推送先完成。

## 用户目标

保留「记言 · Minutes」名称及现有整理能力。用户添加文件、输入自然语言要求后，系统识别关键词、整理目标及方向，依次检索、整理并提供两个独立 TXT 文件：整理内容与核查参考。

## 实现方式与取舍

建议在现有本地 Web 应用内增加 Agent 工作台，复用现有导入、索引、搜索、脱敏、授权、生成与文档服务。这样保留已有数据与配置，减少重复实现，可较快验证完整流程。

独立桌面应用或新的云端 Agent 平台会增加安装、迁移和隐私范围，不符合本轮沿用现有本地流程的要求。无需新增模型供应商或安装 Agent 框架。

## 交互流程

1. 添加现有支持的聊天文件、截图或粘贴文字；展示解析预览。部分成功仍需单独确认接受跳过，没有有效内容时不能继续。
2. 输入自然语言要求，例如「整理这段聊天里有关创业的想法，列出各方观点和分歧」。
3. Agent 生成可修改的任务卡：关键词、整理方向（观点／想法／方法／综合）与整理目标。无法确定时明确显示默认值，不能悄悄丢弃原指令。
4. 本地检索并展示匹配数量；按已有规则加入上下文。没有命中时提示调整要求，不能生成缺乏依据的成果。
5. 展示完整脱敏外发正文、模型与预算；用户逐次授权后才向已配置的 DeepSeek 发送。取消不会发送正文。
6. 显示理解要求、筛选资料、等待授权、整理、完成／失败等可恢复任务状态；不展示模型内部思考链。
7. 预览并分别下载「整理内容.txt」与「核查参考.txt」。保留原有查看、编辑和历史文档能力。

## 两个输出文件

- 整理内容：UTF-8 纯文本，包含题目与现有生成正文，保留核查编号，不混入独立来源附录。
- 核查参考：UTF-8 纯文本，包含与正文编号对应的来源定位、发言者代称、时间（未知时标明）、必要原文摘录及验证限制；明确区分导入内容和 AI 延伸解释。它是可核查的资料，不是模型内部推理。
- 两文件必须属于同一不可变文档版本，以一次确定性映射生成正文核查编号和参考编号；包含聊天消息／截图段落的本地定位。原文已清理时，仍输出两文件，但参考文件只说明依据已不可查看，不能补造或重新保留摘录。
- 用户编辑版明确提示：结构化参考对应 AI 原始版本，未自动核验用户新增或改写的文字。平台托管的参考 TXT 及临时文件纳入原文清理范围。
- 带摘录的参考文件明确披露：删除平台原文不会删除用户已经下载的摘录。

## 边界与实现约定

- 本地单用户应用与现有数据／导出路径保持不变；仅现有 AI 步骤可以联网。
- 任务理解优先在本地完成；任何新增模型调用都须单独说明其外发内容、预算与授权，不隐式增加费用。
- 本轮不更换 v10 总结提示词、生成输入结构或分段综合逻辑。检索使用提取关键词，现有生成 `topic` 参数保留完整自然语言要求，避免丢失用户约束；完整要求与正文一起进入脱敏预览。不新增目的字段或自行恢复已撤回的写作规则。
- 本地规则不宣称理解任意复杂指令；显示可编辑的理解结果。要求、关键词、方向或范围变更后，旧预览和授权立即失效。
- 原文 7 天保留、文档版本长期保留及原文删除后的边界沿用已修复规则。
- 不自动登录，不读取客户端聊天目录，不扩大权限，不执行用户文档中嵌入的指令。
- 保持当前支持的文件格式，不声称支持未经验证的真实微信／QQ 导出格式。

## 验证

- 指令解析：中文多关键词、四方向、模糊／空指令、超长内容、修改任务与重新解析。
- 完整任务：文件导入、部分成功确认、指令解析、本地匹配、授权前零外发、取消与失败重试。
- 输出：两个 TXT 文件、同一版本、正文与依据编号一致、中文编码、原文已删除时的明示行为。
- 后端全套、前端单测／类型检查／构建及合成端到端测试通过；合成结果不代替真实模型质量验收。
