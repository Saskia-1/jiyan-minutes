# 截图 OCR 与笔记文字导入设计

日期：2026-10-12
状态：方案已在对话中确认；本规格待用户审阅，尚未授权代码实施。

## 目标与边界

用户可以在现有本机网页上传 QQ、微信等聊天截图和笔记／网页截图，也可以直接粘贴笔记正文。系统在本机识别图片文字，并把图片建议归为“聊天”“笔记／网页”或“不确定”；用户可以更正类型、文字和可见元数据，再确认导入。导入后的聊天和笔记可以在同一次主题检索与文档生成中使用，但范围由用户逐项确认。

原始截图保存在本机私有目录，并随所属导入批次删除。OCR、分类和导入不调用外部 AI；生成前仍使用现有外发预览、一次性授权、排除、预算及严格证据校验。Dify 接入、QQ／微信自动读取、图片语义理解、向量检索和新总结方向均不在本次范围。

## 当前实现与必须处理的差距

- `api/imports.py`、`domain/imports.py` 和 `ChatImportPanel.tsx` 目前只接受受支持的文本／表格文件或聊天格式粘贴文本；它们不接受图片，普通笔记正文也不能作为独立来源提交。
- `ImportedChatWorkspace.tsx`、`SearchRequest`、`GenerationSelection` 和 `GenerationScope` 以一个已提交导入及一个快照为主要边界。仅添加图片上传控件无法实现跨聊天与笔记批次的范围选择。
- `EvidenceValidator`、`ValidatedEvidence` 和 `EvidenceDrawer` 当前只回填聊天消息。笔记不能通过虚构发送者、会话或时间来冒充消息。
- 现有删除计划按批次追踪快照、生成任务、文档及导出物。混合来源文档与原始图片必须纳入同一可预览的依赖删除范围。

旧 TXT／Paste 聊天导入、搜索、生成、文档版本和导出接口保持兼容；新增能力以独立入口和向后兼容的字段／版本接入。

## 选择的实现方式

采用“分别保存来源、共享检索与生成证据单元”的方式：聊天仍保留真实消息语义；笔记作为独立资料，按可引用段落保存。两类内容在检索结果和生成范围中使用带类型的稳定本地引用，由程序映射为现有生成链路可处理的短引用。模型不能创建来源映射；最终引用仍必须回到当前用户已确认的本地原文。

不采用把笔记转成伪聊天 TXT 的捷径，因为它会混淆作者、发送者、时间与证据。也不采用远程 OCR，因为本次目标是本机私有导入，且远程调用需要另行披露与授权。

本机 OCR 由一个最小 macOS 原生辅助程序调用 Vision／ImageIO，Python 后端负责输入上限、私有暂存、超时和结构化结果校验。辅助程序只返回文字、位置和置信度，不接触 Accessibility，不发网络请求，不输出完整识别正文到普通日志。构建脚本在本机生成忽略版本控制的产物；启动时缺少该产物应明确提示安装／构建步骤，而不是临时改走外部服务。

## 用户流程

1. 在现有“聊天内容”区域选择“上传截图”或“粘贴笔记文字”。聊天文件和聊天文本原入口保留。
2. 截图支持首版 PNG、JPEG；每批最多 20 张，单张最多 15 MiB、总计最多 64 MiB，解码后单张最多 40 百万像素。浏览器保留用户选择的文件顺序，允许在确认前调整顺序和把多张截图归入同一篇笔记或同一段聊天。粘贴笔记单篇最多 1 MiB UTF-8 文本。
3. 后端在本机调用 macOS Vision 的准确文字识别路径，优先识别简体中文和英文，返回文字行、页面位置及可用的置信度。识别、图片解码和分类均受文件、像素、时长及输出大小上限约束；失败不自动转到云端。
4. 本地分类只给出建议。可见的气泡／左右排列／发送者／聊天时间是聊天线索；标题、作者与连续正文是笔记线索。不能充分判断时标为“不确定”。导航栏、点赞数等界面文字仅标记为“可能是界面文字”，不静默丢弃。用户可以改类型、保留或删除识别行。
5. 预览中，聊天按识别到的消息块逐条校对正文、可见发送者、可见时间和顺序；笔记校对标题、可见作者、正文段落及截图顺序。截图缺失上下文时标记“内容可能不完整”。未显示的时间保持未知；手机状态栏时间不得当成发送或发布日期。无法确定的发送者、作者也保持未知。
6. 只有用户确认最新预览指纹后才提交。完全相同图片的哈希重复可明确提示；部分重叠截图只能提示可能重复并供用户核对，不能用模糊去重静默删除内容。提交后来源内容不可原地改写；更正应创建新的导入修订或重新导入，旧文档的冻结证据不被覆盖。
7. 在整理区域，用户选择要纳入的聊天会话、笔记以及具体候选消息／笔记段落。关键词只在这些已选来源内本地检索；可继续逐项排除。生成前展示实际选中条目、来源类型、可外发文字、未知时间状态及调用预算，取得新的单次授权后才调用现有 Provider。
8. 文档沿用现有编辑、版本、Markdown 和 DOCX 导出。统一证据入口按来源类型展示原始聊天，或笔记的已确认文字、标题／作者（若有）及本机原截图；普通正文不自动堆叠来源明细。

## 数据与权限契约

- 一个导入批次保存来源类型、本地用户会话所有权、输入顺序、原始文件 SHA-256、私有图片文件引用及已确认的内容单元。图片只通过会话校验的本地接口读取，不向前端暴露文件系统路径。粘贴文字没有图片文件引用。
- 聊天截图产生 `chat_message` 单元，可见发送者与时间为可空值；笔记产生 `note_passage` 单元，标题、作者及发布日期均可空。长笔记按自然段形成可检索、可引用的单元，并保留同属一篇笔记的关系及原顺序。跨来源没有虚构的统一时间线：聊天保留自身时间／顺序，笔记保留篇内和用户确认的导入顺序。
- 每个单元有来源类型、稳定本地 ID、批次 ID、原图／粘贴来源关联、已确认文字及可空的位置。OCR 原始候选与用户校订稿在本机区分保存；只对校订稿建立搜索索引和外发预览。截图证据必须能定位到所属原图；不要求首版自动高亮字符区域。
- 混合搜索对当前会话有权访问、且用户勾选的批次和单元分别检索，再按稳定 ID 合并去重。时间筛选只约束有真实时间的聊天／笔记；时间未知项目必须通过明确的“包含未知时间”选择才能进入范围。
- 新的冻结生成范围记录所有来源批次、单元 ID、来源类型、校订文字摘要、排除项、Provider／模型／Prompt 身份及预算。其指纹、缓存版本与旧单快照范围隔离。对外仍只发送确认后的文字及必要的匿名来源类型，不默认发送原图或真实文件路径。现有短引用映射在整个任务内唯一，并严格拒绝未知、越界或已排除引用。
- 证据校验从当前会话拥有的冻结来源逐项回填并比对原文；引用合法与文字结论是否得到支持继续分别检查。旧聊天文档与旧缓存按原格式读取，新文档记录多来源清单，不将旧 `source_snapshot_id` 误解释为多来源范围。

## 接口与页面接入点

在现有导入区增加专用的截图／笔记预览接口，而不是放宽聊天备份解析器对图片的格式限制。创建预览和每次校订都返回当前预览指纹；提交必须携带该指纹和明确确认。过期、跨会话或校订后使用旧指纹都拒绝提交。已确认的批次仍通过现有“已导入批次”区域恢复与管理。

现有 `ImportedChatWorkspace` 从“当前单批次”扩展为用户明确选中的来源集合；其余三个主要区域“关键词与方向”“可选修改”“预览下载”不重新设计。跨来源搜索、生成范围与 Evidence API 使用可区分类型的引用，同时保持原聊天专用请求和历史文档响应可用。前端严格解析器同步识别新增可选字段，不放宽为任意对象。

## 删除、失败与安全

截图文件位于应用管理的私有目录，权限仅允许当前用户访问；不创建可由浏览器任意请求的静态图片目录。文件名由程序生成，不信任上传文件名或路径。损坏图片、超限、空 OCR、服务端 OCR 不可用和分类不确定均给出可理解的预览状态，不自动提交、不自动调用外部服务。分类不确定可以由用户选择类型后继续；空 OCR 可以放弃该图或改为手动粘贴文字，但不能把空内容提交为有效证据。

删除某导入批次时，现有删除预览需明确列出该批次原图、OCR／校订文字、索引，以及引用它的混合生成任务、文档版本和导出物。用户确认后按现有可恢复的清理流程删除这些依赖；不能留下仍声称“证据已验证”却无法回填原图／原文的文档。删除一个混合文档依赖的来源批次，会使该文档及其版本／导出物进入同一删除预览，而不是悄悄留下断链证据。其他未依赖该批次的来源保持不变。

## 分阶段交付与验收

第一阶段完成本地 OCR、分类建议、手工校对、原图私有保存、普通笔记粘贴与可恢复的导入批次；尚未接通混合生成时，页面必须明确提示“已导入，暂不可跨来源整理”，不能伪装完成全链路。

第二阶段完成跨聊天／笔记的逐项范围选择、本地检索、排除、冻结外发预览、严格证据回填、文档版本／导出以及依赖删除。两阶段合并验收后才向用户宣布完整功能可用。

自动化测试使用合成截图和文字，不把用户真实截图或聊天写进仓库：覆盖明显聊天、明显笔记、只有中间正文的“不确定”截图，中文／英文混排、低置信度、裁切段落、重复／重叠图片、无发送者／时间、预览校订后旧指纹拒绝、跨会话访问拒绝、已排除单元不能进入外发或证据、跨批次引用不串用、删除影响清单与清理恢复。浏览器验收从上传和粘贴开始，经过校订、刷新恢复、混合搜索、排除、FakeProvider 生成、证据查看、Markdown／DOCX 导出和删除；原有 TXT／Paste 聊天链路需回归通过。真实 Provider 调用不属于本设计实施的自动验收，仍需单独预览与授权。

完成标准是：用户不需要伪造聊天格式就能保存笔记；图片建议类型可更改；截图文字须经用户确认；已排除或未勾选的任何内容不会出现在外发范围；每条生成证据能回到原始本地来源；删除批次能按预览移除原图及依赖；原有聊天流程继续可用。

技术依据：[Apple Vision — Recognizing Text in Images](https://developer.apple.com/documentation/vision/recognizing-text-in-images)。
